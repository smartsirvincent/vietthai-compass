# CMS 編輯與前台同步修正

## 已確認的問題

- 雲端讀取失敗會回傳範例內容；後續儲存可能把範例覆蓋到正式資料。
- 更新採整份 JSON 讀取後覆蓋，並行操作可能互相覆蓋。
- 切換編輯對象時，未受控欄位及城市分區元件可能保留上一筆狀態。正式後台已重現此情況。
- 各類更新只清除部分前台頁面，分類、關聯內容及舊網址可能仍顯示快取。
- 文章中的商家介紹與特色只有關聯商家存在時才呈現。
- user 的圖片上傳被 middleware 攔截。
- 相同 Slug 的新增會覆蓋既有紀錄；更改城市或商家網址沒有同步關聯。
- 正式站逐頁查核發現，Lacàph 商家、Lacàph 文章及 Bui Vien 商家因 Slug 含重音文字或空白而回傳 404。頁面現在先比對原始 Slug，再比對 URL 解碼結果，保留原有網址。

## 修正後的行為

- 雲端讀取失敗或主文件不存在時回報錯誤，不再自動回填範例。
- 儲存先以交易鎖定 `cms_documents` 的 `default` 紀錄，再合併本次修改。
- 表單帶入該筆內容的版本雜湊；舊版本、重複網址及無效城市分區會拒絕儲存。
- 每次成功修改前，將上一份原始內容寫入 `cms_document_revisions`，備份與修改在同一交易完成。備份表啟用 RLS，不提供匿名讀取 API。
- 錯誤時保留表單輸入；送出時顯示處理狀態，成功後重新載入剛儲存的資料。
- 選到尚未上傳完成的照片時，暫停儲存並提示先完成上傳。
- 前台內容頁及 sitemap 在請求時讀取資料，更新後也清除整站路由快取。
- 改名同步城市與商家關聯；仍被使用的城市、分區不允許直接刪除。
- admin 可在網站設定下載目前的 JSON 內容備份，user 無法存取此端點。

## 驗證

`npm test` 使用隔離的 PostgreSQL driver 測試替身檢查並行合併、版本衝突、交易 rollback、備份、空資料拒絕回填、重複 Slug、關聯更新及欄位保存。這不是實際 PostgreSQL 整合測試。

瀏覽器測試涵蓋新增切換到編輯的欄位載入，以及儲存驗證失敗後的文字、換行、標籤保留。另以本機 HTTP 測試確認 user 可到達圖片上傳端點，但商家管理及備份仍遭權限阻擋。

正式資料讀取與備份確認有 18 篇文章、18 間商家、4 個城市，沒有失效的商家／城市關聯。以 Lacàph 商家的原內容儲存成功，確認雲端交易及備份流程可執行。

## 備份與恢復

目前內容可由後台「網站設定 → 下載目前內容備份」取得。

歷史版本保存在雲端 `cms_document_revisions`，欄位為 `id`、`document_key`、`value`、`created_at`。修正啟用前已遭覆寫的資料不會因此自動重建；需比對既有外部備份或原稿。恢復時應先比對指定紀錄的差異，保留目前版本並只恢復需要的欄位，避免覆蓋較新的其他修改。

Vercel 將環境變數標示為 sensitive，CLI pull 不會取得明文。空白下載值不代表正式環境沒有設定資料庫，不應用此檔覆蓋 Vercel 的正式變數。
